01 Entorno de desarrollo

Linux

Mini Lab utiliza Linux nativo como entorno de desarrollo para trabajar con la toolchain de Rust y el entorno de simulación.

i

Los pasos de esta guía están pensados para realizarse sobre Linux instalado de forma nativa. Otros entornos no forman parte del alcance actual de Mini Lab.

Antes de continuar

  • ✓
    Linux instalado de forma nativa Ubuntu, Debian, Arch o similar
  • ✓
    Conexión a internet activa Para descargar paquetes y la toolchain
  • ✓
    Acceso a una terminal Bash o Zsh
  • ✓
    Permisos para instalar herramientas Los vamos a necesitar durante la configuración

Si ya tenés Linux instalado y una terminal disponible, podés avanzar directamente al siguiente paso.

02 Rust embebido

Instalá la toolchain

La toolchain reúne las herramientas de Rust que necesitamos para compilar, generar e inspeccionar programas para sistemas embebidos.

01

Rust y rustup

rustup administra las versiones y componentes de Rust. Al instalar Rust con rustup también obtenemos rustc, el compilador, y Cargo, la herramienta que gestiona proyectos, dependencias y compilaciones.

rustup
Administra toolchains, componentes y targets.
rustc
Compila el código fuente escrito en Rust.
cargo
Gestiona el proyecto, sus dependencias y compilaciones.

En Linux, que es el sistema soportado actualmente por Mini Lab, podés iniciar la instalación con:

Terminal Linux 
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

Al terminar, para actualizar la terminal actual ejecutá el siguiente comando, o simplemente cerrá la terminal y abrí otra:

Terminal 
source "$HOME/.cargo/env"
02

Agregar el target de compilación

La Raspberry Pi Pico 2 utiliza el microcontrolador RP2350. En Mini Lab vamos a trabajar inicialmente con sus núcleos ARM Cortex-M33.

Para que Rust pueda generar código para esta arquitectura, agregamos el target correspondiente:

Terminal 
rustup target add thumbv8m.main-none-eabihf
¡

Este target genera código ARMv8-M para Cortex-M33 utilizando soporte de punto flotante por hardware.

03

LLVM Tools y cargo-binutils

Las LLVM Tools permiten inspeccionar los binarios generados por Rust. cargo-binutils agrega comandos de Cargo para utilizar herramientas como size, objdump y nm de una forma más cómoda.

Terminal 
cargo install cargo-binutils --locked
rustup component add llvm-tools-preview
04

flip-link

Mini Lab utiliza el template rp-rs para RP2350. Este template usa flip-link durante el enlazado para detectar desbordamientos del stack de forma más segura.

Terminal 
cargo install flip-link --locked
05

cargo-generate

Permite crear un proyecto nuevo a partir de una plantilla ya preparada. Esto evita tener que configurar desde cero los archivos y ajustes que necesita un proyecto bare-metal.

Terminal 
cargo install cargo-generate --locked

El comando instala cargo-generate. Para descargar plantillas vas a necesitar Git, que instalaremos en el paso 3 antes de crear un proyecto.

03 Sistema operativo

Configurá Linux

Sistema actualmente soportado Linux

Ubuntu / Debian APT

05 Primer firmware

Creá y compilá tu primer proyecto

Con el entorno preparado, vamos a crear un proyecto para el RP2350, adaptarlo al entorno de simulación y compilarlo para su ARM Cortex-M33.

¡

Mini Lab utiliza el template rp235x-project-template para evitar configurar manualmente desde cero el linker, el layout de memoria y la estructura básica necesaria para un proyecto bare-metal.

01

Generá el proyecto

Usamos cargo-generate para crear un nuevo proyecto a partir del template oficial de rp-rs.

Terminal 
cargo generate --git https://github.com/rp-rs/rp235x-project-template

Cuando el asistente pregunte el nombre del proyecto, podés utilizar:

Nombre del proyecto 
mini-lab-hello

Si pregunta qué método de flashing querés utilizar, seleccioná:

Flashing method 
none
¡

En esta etapa no programaremos una placa física. El firmware será cargado posteriormente en el simulador, por eso no necesitamos configurar un método de flashing.

02

Entrá al proyecto

Terminal 
cd mini-lab-hello
03

Conocé la estructura del proyecto

El template incluye varios archivos que un proyecto Rust convencional no necesita.

Cargo.toml
Define el proyecto y sus dependencias.
src/main.rs
Contiene el punto de entrada del firmware.
.cargo/config.toml
Contiene configuración de compilación y ejecución para el entorno embebido.
memory.x
Define el layout de memoria que necesita el linker para generar el firmware.
04

Adaptá el LED al simulador

El ejemplo original utiliza GPIO25 porque está pensado para el LED de una Raspberry Pi Pico. La placa RP2350 disponible actualmente en Velxio utiliza una distribución diferente.

Abrí src/main.rs y reemplazá:

Original 
let mut led_pin = pins.gpio25.into_push_pull_output();

por:

Mini Lab / Velxio 
let mut led_pin = pins.gpio15.into_push_pull_output();
i

Más adelante conectaremos un LED virtual a GPIO15. Este cambio corresponde al entorno de simulación actual y podrá revisarse cuando trabajemos con la placa física.

05

Agregá salida serial

Además del LED, vamos a enviar mensajes mediante UART para poder observar la ejecución desde el Serial Monitor del simulador.

Agregá estos imports al comienzo de main.rs:

Rust 
use rp235x_hal::fugit::RateExtU32;
use rp235x_hal::uart::{DataBits, StopBits, UartConfig};

Después de inicializar los pines, agregá la configuración de UART0:

Rust UART0 
let uart_pins = (
    pins.gpio2.into_function(),
    pins.gpio3.into_function(),
);


let mut uart0 =
    hal::uart::UartPeripheral::new(
        pac.UART0,
        uart_pins,
        &mut pac.RESETS,
    )
    .enable(
        UartConfig::new(
            115200.Hz(),
            DataBits::Eight,
            None,
            StopBits::One,
        ),
        clocks.peripheral_clock.freq(),
    )
    .unwrap();


uart0.write_full_blocking(b"Mini Lab iniciado\r\n");

Finalmente, reemplazá el loop principal por:

Rust Loop 
loop {
    info!("on!");
    led_pin.set_high().unwrap();
    uart0.write_full_blocking(b"LED ON\r\n");


    delay.delay_ms(500);


    info!("off!");
    led_pin.set_low().unwrap();
    uart0.write_full_blocking(b"LED OFF\r\n");


    delay.delay_ms(500);
}
i

UART0 utiliza GPIO2 como TX y GPIO3 como RX a 115200 baudios. En el siguiente paso utilizaremos el Serial Monitor de Velxio para observar estos mensajes.

06

Compilá el firmware

El template ya está preparado para utilizar el target ARM del RP2350 que instalamos anteriormente.

Terminal Release 
cargo build --release
✓

Si Cargo finaliza sin errores, el firmware fue compilado correctamente.

07

Encontrá el firmware

Cargo guarda el ejecutable compilado dentro del directorio correspondiente al target.

Firmware ELF 
target/thumbv8m.main-none-eabihf/release/mini-lab-hello
i

Aunque el archivo no tenga una extensión visible, es un ejecutable ELF ARM. Velxio puede cargar este archivo directamente, por lo que no necesitamos convertirlo a BIN o UF2.

08

Inspeccioná el firmware

Podemos utilizar cargo-binutils para comprobar qué secciones forman parte del binario y cuánto espacio ocupa cada una.

Terminal Opcional 
cargo size --release -- -A

Ya tenemos código compilado específicamente para el RP2350. El siguiente paso será cargarlo y comprobar su ejecución en Velxio.

06 Simulación

Ejecutá tu firmware en Velxio

Velxio es un entorno de simulación que permite ejecutar firmware para microcontroladores y probar su comportamiento sin utilizar hardware físico. En Mini Lab lo utilizaremos para cargar el firmware que compilamos con Rust, conectar componentes virtuales y comprobar su funcionamiento.

i

En este primer recorrido vamos a comprobar dos aspectos del firmware: una salida GPIO mediante un LED virtual y una salida UART mediante el Serial Monitor de Velxio.

i

Velxio no dispone actualmente de la misma Raspberry Pi Pico 2 utilizada como referencia por Mini Lab. Para este recorrido utilizamos una Pimoroni Pico Plus 2 W, que también pertenece a la familia RP2350. Algunas conexiones y GPIO pueden diferir entre ambas placas.

01

Creá un proyecto en Velxio

Abrí Velxio desde el navegador y creá un nuevo proyecto de simulación.

Abrir Velxio ↗

Seleccioná como placa:

Placa virtual 
Pimoroni Pico Plus 2 W
02

Conectá un LED a GPIO15

Agregá un LED y una resistencia al circuito virtual. Utilizaremos GPIO15 porque es el pin que configuramos en el firmware durante el paso anterior.

1
GPIO15

Conectá GPIO15 a una resistencia de aproximadamente 220 Ω a 330 Ω.

2
LED

Conectá la resistencia al ánodo del LED.

3
GND

Conectá el cátodo del LED a GND.

i

El template original utiliza GPIO25. Lo reemplazamos por GPIO15 porque la placa virtual utilizada en este recorrido no expone GPIO25 de la misma manera.

03

Cargá el firmware

Utilizá la opción Upload Firmware de Velxio y seleccioná directamente el ejecutable ELF que generó Cargo:

Firmware ELF ARM 
target/thumbv8m.main-none-eabihf/release/mini-lab-hello
i

No necesitás convertir el archivo a BIN o UF2. Velxio puede recibir directamente el ELF generado por Cargo y preparar internamente la imagen que utiliza el simulador.

04

Verificá que el firmware fue reconocido

Al cargar el archivo, Velxio puede mostrar una advertencia indicando que detectó firmware ARM mientras la placa seleccionada es una Pimoroni Pico Plus 2 W.

Velxio 
detected ARM architecture, but current board is Pimoroni Pico Plus 2W. loading anyway

En este recorrido esa advertencia es esperada. Después de procesar el archivo, Velxio debería indicar:

Velxio 
loaded ELF firmware ARM -> binary
✓

Este mensaje confirma que Velxio reconoció el ELF ARM y cargó el firmware en el simulador.

05

Ejecutá el firmware

Iniciá la simulación desde Velxio y observá el LED conectado a GPIO15.

✓

Si el LED se enciende y apaga aproximadamente cada 500 ms, el firmware Rust está ejecutándose correctamente en el RP2350 virtual.

06

Abrí el Serial Monitor

Abrí el Serial Monitor de Velxio para observar los mensajes enviados mediante UART por el firmware.

Deberías ver una salida similar a:

Serial Monitor 115200 baud 
Mini Lab iniciado
LED ON
LED OFF
LED ON
LED OFF
...
✓

Si el LED parpadea y el Serial Monitor muestra los mensajes, verificamos tanto la salida GPIO como la comunicación serial del firmware.

✓

Primeros pasos completados

Tu primer firmware está funcionando

Preparaste el entorno, compilaste firmware Rust para RP2350, cargaste directamente el ELF en Velxio y comprobaste su ejecución mediante GPIO y salida serial. Ya podés comenzar con las actividades de Mini Lab.
