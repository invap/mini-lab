03 Prepará

Prepará el proyecto para leer el botón

En Blinky utilizamos un temporizador para controlar cuánto tiempo permanecía encendido o apagado el LED. Ahora el estado del LED va a depender directamente del botón, así que ya no necesitamos generar esperas.

Eliminá la temporización

Retirá los imports utilizados exclusivamente para configurar los clocks y generar los retardos del Tutorial 2.

Eliminar Imports 
use rp235x_hal::clocks::init_clocks_and_plls;
use rp235x_hal::Clock;

También podés eliminar la obtención de los periféricos del procesador, el watchdog, la configuración de clocks y delay, porque ya no los vamos a utilizar.

Eliminar Temporización 
let core = cortex_m::Peripherals::take().unwrap();

let mut watchdog = hal::Watchdog::new(pac.WATCHDOG);

let external_xtal_freq_hz = 12_000_000u32;

let clocks = init_clocks_and_plls(
    external_xtal_freq_hz,
    pac.XOSC,
    pac.CLOCKS,
    pac.PLL_SYS,
    pac.PLL_USB,
    &mut pac.RESETS,
    &mut watchdog,
)
.ok()
.unwrap();

let mut delay =
    cortex_m::delay::Delay::new(
        core.SYST,
        clocks.system_clock.freq().to_Hz(),
    );

Por último, eliminá el loop de Blinky. Vamos a reemplazarlo por una condición que lea constantemente el botón.

i

Conservá pac, sio, la creación de pins y la configuración de GPIO15. El LED sigue formando parte del circuito.

2

Vamos a usar la resistencia pull-up interna del microcontrolador. Por eso no necesitamos agregar una resistencia externa al botón.

05 Entendé

¿Qué hace el pull-up?

Una entrada digital necesita tener un estado definido incluso cuando el botón no está presionado. Para conseguirlo vamos a utilizar la resistencia pull-up interna del RP2350.

El pull-up mantiene GPIO14 conectado débilmente al nivel lógico alto. Por eso, mientras el botón está suelto, el microcontrolador lee HIGH.

Cuando presionamos el botón, GPIO14 queda conectado directamente a GND. El nivel del pin pasa entonces a LOW.

Botón suelto HIGH
→
Botón presionado LOW
i

Puede parecer al revés de lo esperado, pero en este circuito LOW significa que el botón está presionado. Este tipo de conexión suele llamarse activo en bajo o active-low.

06 Programá

Configurá GPIO14 como entrada

Primero importá el trait que nos permite consultar el estado de una entrada digital:

src/main.rs Import 
use embedded_hal::digital::InputPin;

Después de inicializar los pines, agregá la configuración del botón.

src/main.rs GPIO Input 
let mut button = pins.gpio14.into_pull_up_input();
i

into_pull_up_input() configura GPIO14 como entrada y activa su pull-up interno.

Rust

Declaramos button con mut porque la interfaz InputPin necesita acceso mutable al pin para consultar su estado mediante métodos como is_low().

↩

Conservamos la configuración de GPIO15 y OutputPin del Tutorial 2. En este ejercicio solamente estamos agregando una nueva entrada en GPIO14.

07 Experimentá

Controlá el LED con el botón

Reemplazá el loop del Tutorial 2 por una condición que compruebe constantemente el estado del botón.

src/main.rs Loop 
loop {
    if button.is_low().unwrap() {
        led_pin.set_high().unwrap();
    } else {
        led_pin.set_low().unwrap();
    }
}
Resultado esperado

Mientras mantengas presionado el botón, el LED debería permanecer encendido. Al soltarlo, debería apagarse.

Rust

if permite ejecutar un bloque de código solamente cuando una condición es verdadera. En este caso, button.is_low() es verdadero cuando el botón está presionado.

i

Si el botón está presionado, ejecutamos set_high() y encendemos el LED. Si no lo está, else ejecuta set_low() y lo apaga.
