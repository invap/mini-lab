03 Prepará

Prepará el proyecto para el sensor

En el Tutorial 3 utilizamos GPIO14 para leer un botón y GPIO15 para controlar un LED. En este tutorial ya no necesitamos ninguno de esos dos periféricos.

Eliminá el código del botón y del LED

Retirá los imports de entrada y salida digital:

Eliminar Imports GPIO 
use embedded_hal::digital::InputPin;
use embedded_hal::digital::OutputPin;

Eliminá también la configuración de GPIO14 y GPIO15:

Eliminar GPIO 
let mut led_pin = pins.gpio15.into_push_pull_output();
let mut button = pins.gpio14.into_pull_up_input();

Por último, eliminá el loop que controlaba el LED con el botón.

Eliminar Loop del Tutorial 3 
loop {
    if button.is_low().unwrap() {
        led_pin.set_high().unwrap();
    } else {
        led_pin.set_low().unwrap();
    }
}
i

Conservá pac, sio y la creación de pins. Vamos a reutilizar esos recursos para configurar UART e I²C.

04 Entendé

¿Qué es el MPU6050?

El MPU6050 integra un acelerómetro y un giroscopio. El acelerómetro permite medir aceleraciones sobre los ejes X, Y y Z, mientras que el giroscopio permite medir rotación alrededor de esos mismos ejes.

Aceleración X · Y · Z
+
Rotación X · Y · Z
i

En este primer contacto vamos a trabajar solamente con el acelerómetro. El giroscopio se puede explorar más adelante utilizando el mismo bus I²C.

06 Prepará

Prepará clocks y UART

Vamos a volver a utilizar comunicación serial para mostrar las mediciones en el Serial Monitor. Es la misma idea que trabajaste en el Tutorial 1 — Serie / UART .

Agregá los imports que vamos a utilizar:

src/main.rs Imports 
use core::fmt::Write;
use cortex_m::delay::Delay;
use embedded_hal::i2c::I2c;
use hal::clocks::{Clock, init_clocks_and_plls};
use hal::uart::{DataBits, StopBits, UartConfig};
use rp235x_hal::fugit::RateExtU32;
use rp235x_hal::gpio::{FunctionI2C, Pin};

Dentro de main(), después de obtener pac, recuperá también los periféricos del procesador y configurá los clocks:

src/main.rs Clocks 
let mut pac = pac::Peripherals::take().unwrap();
let core = cortex_m::Peripherals::take().unwrap();
let sio = hal::Sio::new(pac.SIO);

let mut watchdog = hal::Watchdog::new(pac.WATCHDOG);

let clocks = init_clocks_and_plls(
    12_000_000,
    pac.XOSC,
    pac.CLOCKS,
    pac.PLL_SYS,
    pac.PLL_USB,
    &mut pac.RESETS,
    &mut watchdog,
)
.ok()
.unwrap();

Después de este bloque, mantené la creación de pins:

src/main.rs GPIO 
let pins = hal::gpio::Pins::new(
    pac.IO_BANK0,
    pac.PADS_BANK0,
    sio.gpio_bank0,
    &mut pac.RESETS,
);

Ahora configurá UART0 utilizando GP2 para TX y GP3 para RX:

src/main.rs UART0 
let uart_pins = (
    pins.gpio2.into_function(),
    pins.gpio3.into_function(),
);

let mut uart0 =
    hal::uart::UartPeripheral::new(
        pac.UART0,
        uart_pins,
        &mut pac.RESETS,
    )
    .enable(
        UartConfig::new(
            115200_u32.Hz(),
            DataBits::Eight,
            None,
            StopBits::One,
        ),
        clocks.peripheral_clock.freq(),
    )
    .unwrap();
Rust

Esta vez declaramos uart0 con mut porque vamos a utilizar writeln!, que necesita escribir sobre UART mediante acceso mutable.

07 Configurá

Configurá el bus I²C

Ahora configuramos GP4 y GP5 para que dejen de funcionar como GPIO comunes y pasen a formar el bus I²C0.

src/main.rs I²C0 
let sda_pin: Pin<_, FunctionI2C, _> =
    pins.gpio4.reconfigure();

let scl_pin: Pin<_, FunctionI2C, _> =
    pins.gpio5.reconfigure();

let mut i2c = hal::I2C::i2c0(
    pac.I2C0,
    sda_pin,
    scl_pin,
    400_u32.kHz(),
    &mut pac.RESETS,
    &clocks.system_clock,
);
i

SDA transporta los datos entre el microcontrolador y el sensor. SCL transporta la señal de reloj que sincroniza esa comunicación.

i

Configuramos I²C0 a 400 kHz. Varios dispositivos pueden compartir SDA y SCL siempre que tengan direcciones I²C diferentes.

08 Entendé

¿Qué son los registros?

El MPU6050 organiza su configuración y sus mediciones en pequeñas posiciones internas llamadas registros.

Cada registro tiene una dirección. Para configurar el sensor o leer un dato, primero indicamos con qué dirección queremos trabajar.

0x75
WHO_AM_I Permite comprobar la identidad del sensor
0x6B
PWR_MGMT_1 Permite configurar el estado de energía
0x3B
ACCEL_XOUT_H Es el comienzo de los registros que contienen los datos del acelerómetro
i

Los valores que comienzan con 0x están escritos en hexadecimal, una representación muy utilizada al trabajar con hardware y registros.

09 Inicializá

Activá e identificá el MPU6050

Primero definimos la dirección que identifica al MPU6050 dentro del bus I²C.

src/main.rs Dirección I²C 
const MPU6050_ADDR: u8 = 0x68;
i

No confundas la dirección 0x68 con las direcciones de los registros. 0x68 identifica al MPU6050 dentro del bus I²C; valores como 0x75 o 0x6B identifican posiciones internas del sensor.

Sacá el sensor del modo de suspensión

Al encenderse, el MPU6050 comienza en modo de suspensión (sleep) para reducir el consumo de energía. Antes de realizar mediciones tenemos que sacarlo de ese estado.

src/main.rs PWR_MGMT_1 
i2c.write(
    MPU6050_ADDR,
    &[0x6B, 0x00],
).unwrap();
i

0x6B selecciona el registro PWR_MGMT_1. Al escribir 0x00 desactivamos el modo sleep y dejamos el MPU6050 preparado para medir.

Comprobá que responde

Ahora consultamos el registro WHO_AM_I, ubicado en 0x75. El sensor debería responder con su dirección de identificación.

src/main.rs WHO_AM_I 
let mut who_am_i = [0u8; 1];

i2c.write_read(
    MPU6050_ADDR,
    &[0x75],
    &mut who_am_i,
).unwrap();

writeln!(
    uart0,
    "WHO_AM_I: 0x{:02X}",
    who_am_i[0]
).unwrap();
i

write_read() primero envía la dirección del registro que queremos consultar y después lee la respuesta del sensor. En este caso seleccionamos 0x75 y recibimos un byte.

Resultado esperado

Si la comunicación funciona correctamente, el Serial Monitor debería mostrar WHO_AM_I: 0x68.

10 Leé

Leé la aceleración

Los datos del acelerómetro comienzan en el registro 0x3B. Vamos a leer seis bytes: dos para X, dos para Y y dos para Z.

Antes del loop, creá nuevamente un Delay. Lo vamos a usar para mostrar una medición cada 500 ms.

src/main.rs Delay 
let mut delay = Delay::new(
    core.SYST,
    clocks.system_clock.freq().to_Hz(),
);
i

No queremos enviar miles de mediciones por segundo al Serial Monitor. El delay hace que el resultado sea mucho más fácil de observar.

Ahora reemplazá el loop vacío por la lectura completa:

src/main.rs Acelerómetro + UART 
loop {
    let mut accel_data = [0u8; 6];

    i2c.write_read(
        MPU6050_ADDR,
        &[0x3B],
        &mut accel_data,
    )
    .unwrap();

    let accel_x = i16::from_be_bytes([
        accel_data[0],
        accel_data[1],
    ]);

    let accel_y = i16::from_be_bytes([
        accel_data[2],
        accel_data[3],
    ]);

    let accel_z = i16::from_be_bytes([
        accel_data[4],
        accel_data[5],
    ]);

    writeln!(
        uart0,
        "X: {} | Y: {} | Z: {}",
        accel_x,
        accel_y,
        accel_z
    )
    .unwrap();

    delay.delay_ms(500);
}
i

Cada eje utiliza 16 bits, es decir, 2 bytes. Por eso leemos seis bytes en total. i16::from_be_bytes() vuelve a unir cada pareja para obtener el valor correspondiente.

Rust

Utilizamos i16 porque las mediciones pueden tener valores positivos o negativos según la dirección de la aceleración.

↩

writeln! reutiliza la comunicación serial que configuramos antes para enviar cada medición al Serial Monitor.
